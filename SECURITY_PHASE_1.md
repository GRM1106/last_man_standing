# Security phase 1 working notes

## Rendering-sink inventory

- Confirmed unsafe: dynamic `innerHTML` in Admin Pots, Admin Picks, Admin Standings, the player standings table, and the gameweek-processing summary. These paths included database-backed names, emails, pot/team data, selection metadata, and outcomes.
- Remediated: the confirmed sinks now build elements explicitly and assign untrusted values with `textContent` through `ui.js` helpers.
- URL sinks: database-backed badge URLs are accepted only when HTTPS and hosted by `resources.premierleague.com` (or same-origin). Rejected schemes/origins leave the image without a `src` attribute.
- Static trusted markup: one remaining `innerHTML` creates only the fixed “Select approved player” placeholder option in `admin.js`; it has no interpolation or external input.
- Safe assignments: messages, authentication metadata, names, email addresses, API errors, and URL-derived display values use `textContent`. Same-page quick-navigation links are generated from pot UUIDs returned by the database and are assigned through the `href` property.

## CSP origin inventory

- `'self'`: application scripts, styles, fonts, pages, and `/api/fpl`.
- `https://enzdvsppduyqtpdeseyh.supabase.co`: Supabase Auth, PostgREST, and RPC HTTPS requests.
- `wss://enzdvsppduyqtpdeseyh.supabase.co`: Supabase client's realtime/WebSocket transport if used.
- `https://resources.premierleague.com`: team badge images generated by the FPL sync SQL.

Google OAuth is a top-level navigation initiated by Supabase Auth, not a page subresource or form submission, so it does not require a Google CSP source. The FPL upstream is contacted only by the server-side `/api/fpl` function and is therefore not in browser `connect-src`.
